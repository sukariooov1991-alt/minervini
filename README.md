# MINERVINI Platform (minervini_v2 Structure)

## Structure
- `analysis/`: active strategy modules for Trend Template, relative strength, VCP, Pullback, accumulation/distribution, quarterly earnings, and market regime. Annual-statement screening code has been removed; the active earnings gate uses the latest quarterly EPS and revenue comparisons.
- `data/`: Storage (`storage_manager.py`), multi-source daily market-data provider (`data_provider.py`), centralized US calendar/session clock (`market_time.py`), S&P 500 symbols (`sp500_symbols.py`), trade levels (`trade_levels.py`), Longbridge realtime client (`longbridge_stream.py`), and Telegram notifier (`telegram_notifier.py`).
- `screener.py`: Daily SEPA candidate scanner.
- `app.py` & `index.html`: Flask backend with `/api/stream` and dark mobile-first UI.
- `Dockerfile`: Container build configuration.

## Daily market-data provider failover

Daily OHLCV candles are fetched automatically in this order:

1. **Yahoo Finance** — primary source.
2. **Stooq** — best-effort public daily CSV fallback. The current endpoint may throttle or deny automated requests and some access paths may require registration/API credentials; this code does not send a Stooq key.
3. **Nasdaq public historical data** — additional automatic fallback with no API key or credentials; uses Nasdaq's public delayed historical endpoint.
4. **Alpha Vantage** — optional final fallback. Set `ALPHAVANTAGE_API_KEY` in the service environment to enable it.

Longbridge is reserved exclusively for realtime prices through one persistent WebSocket QuoteContext. The app subscribes to both Quote and Trade push types and registers both callbacks. Watchlist symbols are reconciled against provider-confirmed Quote+Trade subscriptions, and missing symbols are added through the existing context. Quote `last_done` and the newest valid execution in each PushTrades event feed the same ordered live-price pipeline; the card retains the exact feed source (`longbridge_websocket` or `longbridge_trade_websocket`). Quote callbacks publish the price immediately to the card and enqueue technical recalculation on four workers; dispatch allows only one active worker per symbol and preserves that symbol's FIFO order while different symbols are processed in parallel. Volume-only PushQuote messages count as stream activity and update cumulative candle volume using the last displayed price without inventing a new price tick or changing the displayed price's freshness timestamp. Provider timestamps reject older price pushes when timestamps are available. The app retains evolving session OHLC in memory between ticks so open/high/low are not reset on each push; individual ticks are not written into historical SQLite candles. No REST quote-snapshot fallback is currently used. Longbridge is never called by the daily or historical candle provider. The realtime adapter consumes actual WebSocket PushQuote `last_done` / `trade_session` and PushTrades execution price / timestamp / session fields; it does not fetch or merge REST SecurityQuote snapshots. The session label therefore describes the session attached to each received push. US overnight quotes are enabled with `LONGBRIDGE_ENABLE_OVERNIGHT=true` (already set in `render.yaml`); the same Longbridge LV1 quote permission covers pre-market, regular, after-hours, and overnight US stock quotes.

A failed or empty provider no longer aborts the symbol download: the next provider is attempted, and the successful source is written to the application log. If all providers fail, the error lists each provider's failure. The provider failover does not remove symbols from the S&P 500 universe or alter the screening criteria.

Nasdaq's public endpoint does not require a key, but it is an undocumented public endpoint and may change or throttle automated requests; its prices may be delayed. Stooq access is best-effort: automated downloads may be blocked, throttled, or require a key/CAPTCHA, so the application automatically continues to Nasdaq if Stooq fails. Alpha Vantage requires an API key and its free-tier limits may restrict large scans. Yahoo daily history uses raw (unadjusted-for-dividends) OHLC so pivots and trade levels share the same traded-price basis as Longbridge quotes. Legacy Yahoo caches created with dividend-adjusted OHLC are automatically rebased to raw OHLC on their next refresh. Provider adjustment conventions can still differ, so a fallback source is treated as an independent history and triggers a full rebase rather than being mixed into the prior provider's candles.


## Permanent historical and event-data cache

The SQLite database on Render's persistent disk is the source of truth for daily history and cached research data. The cache is independent of watchlist cards; deleting a card never deletes its candles, fundamentals, news, or earnings events.

- **Daily OHLCV:** retain the latest 300 completed daily candles per symbol (including the market index); symbols with fewer than 300 sessions since IPO retain all available completed candles. These rows are durable historical records in SQLite on Render's persistent disk, not a 20-hour cache. The first load fetches the available history and stores only the latest 300 completed sessions. Each subsequent completed US trading session is upserted by (symbol, date), and the oldest row is trimmed in the same database operation so the rolling window remains exactly 300 bars once 300 sessions exist. Deleting a watchlist card does not delete its candle history. The current, unfinished US session candle is excluded.
- **Refresh cadence:** an independent background worker runs after the actual US regular close plus a one-hour provider-publication buffer, including early-close days. It uses the US equity holiday calendar, so weekends and exchange holidays do not trigger a daily candle request. The decision is based on the latest completed exchange-session date stored for the symbol, never on the age of the cache. If today's completed bar is not yet available from the provider, the worker retries after 15 minutes. A scan during the day reads the same permanent SQLite history and does not force a historical download. The short overlapping 10-day provider window is only for catching up missed sessions; it is merged into the permanent 300-bar history, not used as a replacement cache. Failed refreshes preserve the last good candles and are retried after a 15-minute cooldown. A preserved but stale cache is reported as a refresh failure and excluded from that scan's RS ranking, market breadth, and stock analysis; its existing watchlist card and stored history are retained until a successful refresh.
- **Quarterly fundamentals / earnings:** the background research pass checks every symbol every 4 hours, while per-symbol caching limits valid quarterly EPS/revenue provider fetches to once every 24 hours; empty/unavailable responses retry after 6 hours. The screener retains the latest four available quarterly EPS-growth and revenue-growth readings and reports whether EPS growth accelerated versus the immediately preceding reported quarter. Acceleration is a diagnostic preference, not a mandatory gate by default. Year-ago EPS and revenue are matched only from the same reported quarter, with a 14-day date tolerance for 52/53-week fiscal calendars; an unrelated older quarter is not substituted when the comparable period is missing. Newly reported quarter values are persisted in SQLite. A changed report for the same symbol and quarter updates that quarter's event record instead of creating a duplicate. If a refresh request fails, the last good statements remain cached and their events are preserved, but the screener marks that symbol's fundamentals as unknown until a successful refresh rather than treating stale values as current.
- **News:** the background research pass checks every S&P 500 symbol every 4 hours; the durable per-symbol cache means non-empty news is requested from Yahoo no more than once every 4 hours. Empty/error responses retry after 1 hour. Both the latest response and individual article history are stored in SQLite; duplicate articles are ignored while distinct articles sharing a timestamp are retained.
- **Retention:** news and earnings event history has no rolling row cap and is separate from watchlist_cards. The database can grow over time and should be monitored.

Two independent background maintenance threads run separately from the Scan button: the research scheduler refreshes durable news/fundamentals caches every 4 hours, including weekends and exchange holidays; the daily-history scheduler checks the permanent candle cache after the US close plus the one-hour publication buffer. A slow research/news refresh therefore cannot block the completed-session OHLCV refresh. The per-symbol cache timestamps control provider calls: news refreshes every 4 hours, quarterly fundamentals every 24 hours, and failed/empty results use shorter retry intervals. Fresh data is read from SQLite instead of being downloaded again. Both schedulers run inside the single Gunicorn web worker configured in render.yaml and persist data to the Render disk; the Gunicorn worker-exit hook signals them to stop before the process is replaced.

## Pullback entry path

Pullback is evaluated independently from VCP. The screener keeps a recent-decline candidate visible, then waits for the current candle to turn upward before confirming a Pullback entry. Because Minervini's published material does not define one universal numeric turn-up trigger or fixed stop, the current candle test is an explicit implementation proxy (close above its open and previous close), not a quoted Minervini formula. The first confirmed Pullback trigger and its support low are frozen in the saved card across subsequent price ticks; they are cleared when the turn-up confirmation is lost and reset if a new lower structural low forms. The pullback's recent low anchors the structural risk level. Saved cards are revalidated on startup against completed daily candles: both VCP/breakout and Pullback confirmations are recalculated so persisted intraday signals cannot remain active after a restart. Trade targets are calculated as a 2R-to-3R ladder from the shared stop. A valid structural low is preferred; when unavailable, the plan uses a clearly labeled fallback stop 2 × Wilder ATR(14) below the setup pivot. This ATR multiple is an explicit project setting, not a universal Minervini rule. Risk-plan completeness is informational and does not suppress a qualified setup alert. The plan is rejected if any displayed entry tranche would require more than a 10% stop.


## Strategy source alignment and implementation boundaries

The application distinguishes rules explicitly described by Mark Minervini from numeric proxies required to automate chart interpretation. A numeric threshold below that is not stated in the cited material is a project setting, not a claim about a universal Minervini rule.

### Source-defined principles

- **Trend Template:** all eight Stage 2 criteria are applied, including price above the 50/150/200-day averages in the specified order, a rising 200-day average, at least 30% above the 52-week low, within 25% of the 52-week high, and an IBD RS Rating of at least 70 (the code's 493-symbol percentile is only an approximation). Source: *Trade Like a Stock Market Wizard*, Chapter 5.
- **VCP:** volatility contracts from left to right, usually across 2–6 contractions; successive contractions are roughly half the previous one, with reasonable variation; volume dries up at key points; the entry is the pivot break with expanding volume. Source: *Trade Like a Stock Market Wizard*, Chapter 10.
- **Pullback:** Minervini waits for price to begin turning upward and does not buy while it is falling. Pullbacks can occur within a base, at a prior breakout level, or occasionally at the 20/50-day averages after a breakout. The source does not prescribe one universal numeric turn-up formula. Source: *Momentum Masters* (2015), Minervini interview, and *Trade Like a Stock Market Wizard*, Chapter 11.
- **Risk:** establish a predetermined stop before entry; keep the maximum loss no greater than 10%; maintain at least a 2:1 win/loss ratio and aim for 3:1. Stop placement and profit-taking are tied to actual trading results and market conditions, not a universal ATR target formula. Source: *Trade Like a Stock Market Wizard*, Chapters 12–13.

### Watchlist card lifecycle

A completed scan can mark an existing card ineligible and show the failed filter reason, but it never automatically deletes the card or unsubscribes it. Cards remain visible for continued monitoring until the user explicitly removes them. Transient provider/analysis failures preserve the last known eligibility state.

### Explicit project heuristics (not presented as Minervini's exact rules)

- RS rating is a percentile rank calculated among symbols with valid 253-close histories in this repository's fixed 493-symbol list, using a 40/20/20/20 weighted 63/126/189/252-session return score (253 closes are required for the full 252-session leg). Ranking is refused when valid-history coverage is below 80% of the eligible scan universe. The list is not auto-synchronized with S&P constituent changes, and this score is not the proprietary IBD RS Rating or a published Minervini-specific RS calculation. To avoid inflating ranks or market breadth from a small surviving subset during provider outages, both calculations require at least 80% coverage of the eligible scan universe; below that level the metric is UNKNOWN and affected symbols are retained as uncertain rather than treated as failed setups.
- VCP swing-pivot detection, the 0.75 maximum contraction ratio, and 55% very-low-volume-day threshold are mechanical screening proxies for the qualitative VCP footprint. No absolute final-contraction percentage cap is imposed by default; the final T is judged relative to the preceding contraction, consistent with Minervini's description of successive contractions shrinking to about half (plus or minus a reasonable amount). The final contraction's average volume must be below its 50-day average, and at least one very-low-volume day must occur inside the final contraction/right-side pivot window; a negative 40-day volume slope is diagnostic only and is not required to pass. This matches the source's emphasis on volume drying up at the final contraction/pivot rather than somewhere unrelated in the base.
- Breakout confirmation requires a close above the pivot and volume strictly above the 50-day average (1.0x baseline). Larger volume surges are preferable, but neither a universal +35% increase, a fixed 0.25% pivot buffer, nor a 0.65 candle-close-location gate is required by default. Optional parameters remain available for explicit experiments.
- The 20% EPS growth floor is the lower end of the 20–25% quarterly growth guidance discussed in the source. Revenue growth is required to be positive by default and its actual rate is reported; no universal 10% sales threshold is imposed. Accumulation uses the comparison of up-volume/down-volume and the count of above-average-volume up sessions versus down sessions, without a fixed 1.5% price-move threshold or 1.25x volume premium. The 20/50-session measurement windows, market breadth minimum (25%), and five-distribution-day limit remain explicit project settings rather than universal fixed Minervini thresholds.
- Pullback's five-bar decline window and live-price turn-up candle test are operational proxies. When the official session open is not available from PushQuote, the live candle uses the previous completed close as its reference instead of treating an arbitrary first tick as the open.
- The 5% maximum entry range, five entry tranches, and intermediate 2R-to-3R target steps are application trade-planning outputs, not Minervini's prescribed five-target method. Stop selection prefers the actual structural low; if unavailable, the fallback is 2 × Wilder ATR(14) below the setup pivot. The multiplier is a transparent project setting, not a source-defined Minervini rule. Stop availability/completeness is risk information and must not suppress an otherwise qualified setup alert.

These distinctions are deliberate: preserve the source-defined concepts, keep necessary automation parameters visible, and avoid attributing implementation choices to the author. The built-in `data/market_time.py` calendar covers recurring US equity holidays and common early closes, handles 13:00 ET half-day closes and Longbridge's 20:00–04:00 ET Sunday-through-Thursday overnight sessions (assigned to the next trading date), and centralizes New York timezone/DST conversion. Exceptional one-off exchange closures still require a calendar update.


## Dashboard access protection

All HTTP dashboard routes, including the main page, state API, server-sent event stream, scan start/stop, and watchlist-card deletion, require HTTP Basic authentication. The password is read only from the `MINERVINI_ACCESS_KEY` environment variable; it is never stored in source code or sent in page JavaScript. The username is fixed as `admin`. Configure a long, unique secret for `MINERVINI_ACCESS_KEY` in the Render service environment before using the dashboard. If the variable is missing, the app fails closed with HTTP 503 rather than serving an unprotected dashboard. Browsers will show their native sign-in prompt and reuse the same-origin credentials for the dashboard APIs and event stream.

This HTTP access check does not alter the outbound Longbridge WebSocket client, its subscriptions, quote processing, or realtime price updates. Keep the access key private and rotate it in Render if it is ever exposed.
